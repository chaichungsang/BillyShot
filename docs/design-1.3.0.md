# BillyShot 1.3.0 详细设计 — 演示录屏（核心）

基于 1.2.3 源码。范围：鼠标光圈、点击波纹、聚光灯、演示模式、摄像头圆窗。画笔 / 按键显示 / 只录摄像头 → 1.3.1；放大跟随 → 1.3.2。

## 1. 总体做法
- 所有效果都是**真实画在屏幕上的窗口**，不加防截屏保护 → 录屏（Chromium 桌面采集）和 Zoom/Teams 共享都能看到。录屏管线 recorder.js 不改。
- 控制条、区域边框、倒计时保持「不进画面」（原有 protect()）。
- 新模块 `src/present.js`（主进程）负责：演示层窗口、鼠标位置轮询、点击事件、摄像头圆窗。main.js 只做接线。
- 新功能默认全部关闭；老用户升级后录屏结果完全不变。

## 2. 设置（settings.js 新增 present 段 + 两个快捷键）
```
present: {
  halo: false, haloColor: '#ffd23f', haloSize: 56, haloOpacity: 0.35,
  clicks: false, clickLeft: '#ff4d6d', clickRight: '#3d8bff',
  withRecord: true,              // 录屏时自动显示已开启的光圈/波纹
  spotRadius: 170, spotDim: 0.6,
  camera: false,                 // 录屏时显示摄像头（录屏工具栏的开关也写这里）
  cameraDeviceId: '', cameraShape: 'circle' | 'rounded', cameraSize: 's'|'m'|'l', cameraMirror: true,
  cameraPos: null,               // { cx, cy } 圆窗中心在屏幕上的相对位置 0–1
}
hotkeys.presentMode  Win Alt+Shift+H / Mac ⌃⌘H   演示模式开关
hotkeys.spotlight    Win Alt+Shift+L / Mac ⌃⌘L   聚光灯开关
```
deepMerge 让老用户自动拿到新默认值。快捷键沿用占用检测（红点 + 通知）。

## 3. 演示层（每块屏一个窗口，present.html）
- 透明、无边框、不可聚焦、不进任务栏、置顶 screen-saver 级、`setIgnoreMouseEvents(true)` 鼠标穿透；Windows 上高度减 1px，避免系统把它当成「全屏程序」（会屏蔽通知、影响任务栏）。
- 窗口标题含 “Present”，截图的窗口识别跳过它。
- **何时出现**：演示模式开 / 聚光灯开 / 正在录屏且 withRecord 且（光圈或波纹开）。三者都不满足时窗口销毁（不常驻，零开销）。
- 光圈：小圆 DOM，`transform: translate3d` 移动（GPU 合成）。
- 点击波纹：扩散动画 DOM，左键 / 右键（中键同右键）不同颜色，animationend 后删除，最多同时 12 个。
- 聚光灯：所有屏变暗，鼠标处一个亮圈。用 1/4 尺寸元素画径向渐变再放大 4 倍并 transform 移动，4K 下也只有很小的纹理。
- 鼠标位置：主进程 60Hz 轮询 `screen.getCursorScreenPoint()`（DIP 坐标，不需要任何权限），只在变化时发给鼠标所在屏的窗口，其他屏隐藏光圈。
- 点击：uiohook mousedown（hotkeys.js 改为引用计数共享钩子），位置用当时的 getCursorScreenPoint。Mac 没有辅助功能权限时只提示一次，光圈和聚光灯照常可用。
- 截图（框选截图 / 全屏截图）前先隐藏演示层，截完恢复 → 截图里不会有光圈。
- 屏幕增减 / 缩放变化时重建。

## 4. 摄像头圆窗（camera.html）
- 浮动窗口：圆形或圆角矩形（4:3），小 160 / 中 240 / 大 340（DIP），镜像默认开。悬停显示三个按钮：大小、形状、关闭。拖动用 JS（同控制条做法）。
- 不加防截屏保护 → 直接作为屏幕画面录进去。
- 打开方式：① 录屏工具栏「摄像头」开关（MP4 / GIF 都可用，记到 present.camera）；全屏录屏用设置值。② 录制中控制条按钮。③ 托盘「摄像头画中画」/ 设置页「预览」（不录屏也能开）。
- 位置：记住的位置在录制区域内就用；否则放到区域右下角内侧 20px。区域放不下就自动缩小（最小 96），还放不下就不显示并在控制条提示「区域太小，未显示摄像头」。录制中拖出区域时边框变橙色并提示「不在录制区域内」。
- 开录时序：录制的「正式开始」等摄像头出画（最多 2.5 秒），避免开头几帧是黑圈。
- 错误：被 Zoom 等占用（NotReadableError）、找不到摄像头、Mac 未授权 → 圆窗显示原因 3 秒后关闭，控制条显示警告，录屏照常继续。
- 由录屏打开的圆窗随录屏结束关闭；手动打开的保持。
- Mac：Info.plist 的 NSCameraUsageDescription 改为真实用途；打开前 `askForMediaAccess('camera')`。

## 1.3.1 补丁：摄像头圆窗在 Windows 上显示成方块

- **现象**（Benji 在 Windows 上截图）：形状选「圆形」，白色圆框画出来了，但摄像头画面是一整块方形，四角露在圆框外；录出来的视频里也一样。
- **原因**：原来只靠外层 `.cam` 的 `border-radius + overflow: hidden` 裁 `<video>`。Windows 上 Chromium 会把摄像头 `<video>` 交给显卡的视频叠加层（DirectComposition overlay）单独显示，这条路不吃外层的圆角裁剪，透明窗口里更明显。Linux（软件合成）和 Mac 不走这条路，所以 1.3.0 的自动化测试没发现。
- **修复**（都在 `renderer/camera.html`）：
  1. `.cam` 加 `clip-path: circle(50%)`（圆角方形 `inset(0 round 18px)`），`<video>` 自己也加 `border-radius` + `clip-path`（圆角方形 15px，贴着白边内侧）。
  2. `.cam` 加一个全不透明的 `mask-image`（看不出效果）。带 mask 的层必须先在页面里合成成一张图再上屏，里面的视频不会被单独交给叠加层，所以一定按 CSS 裁剪。
  - 原本还想在 Windows 上加 `disable-direct-composition-video-overlays` 启动参数兜底，但打包时检查发现 Electron 44（Chromium 144）的 BillyShot.exe 里已经没有这个开关（只剩 `enable-…` 和关掉整个 DirectComposition 的 `disable-direct-composition`，后者会影响所有透明窗口，不用），所以去掉了。
- **测试**：`test/camshape_1_3_1.sh`（17 项）：圆形 / 圆角方形 × 镜像开 / 关，截屏核对四角是桌面、中心是摄像头画面、圆内靠边没被多裁；悬停按钮条能点到；全屏录屏的视频帧里四角也是桌面。注意：Linux 上 1.3.0 本来就能通过这些检查（问题只在 Windows 显卡那条路上），所以这些测试是防止以后改坏，**Windows 是否修好要真机确认**。

## 1.3.2：录屏保存——文件夹里出现 .mp4 才算好，控制条显示进度和「已保存」

- **Benji 反馈**：录完以后不知道好了没有，等了几分钟以为还在后台处理。要求：还没进文件夹就显示没好，好了要有明显提示。
- **查日志 + 实际文件**：他那两段 4K 录屏（36 秒、75 秒）按停止后 0.1 秒就保存完了。但 MediaRecorder 写的是「分段 MP4」（fMP4：开头 moov 里时长是 0，没有样本表，数据分在一段段 moof+mdat 里），而且录制中就直接用正式文件名写。结果：文件一开始录就出现在文件夹里；停止后资源管理器读不到时长，看起来像「还没做好」。
- **做法**：
  1. 录制中写到 `BillyShot_xxx.mp4.part`（GIF 是 `.gif.part`），保存完才改名成 `.mp4`。文件名里有 `.part` 就是还没好，看到 `.mp4` 就是好了。改名失败（杀毒软件锁住）重试 8 次，还不行就保留 .part 名字，不丢文件。
  2. `src/mp4fix.js`：把分段 MP4 原地整理成普通 MP4。在文件末尾追加一个完整的 moov（mvhd / tkhd / mdhd 时长，stts / ctts / stss / stsc / stsz / stco 或 co64；轨道起点不为 0 时加 elst），再把旧的 moov 和每个 moof 的类型改成 `free`（只改 4 个字节）。音视频数据不复制、不移动，216 MB 的 4K 文件 170 毫秒。分段之间时长加起来和下一段 tfdt 对不上时，差值记到上一段最后一帧，保证每帧时间戳和原文件一致。末尾不完整的分段（断电 / 进程被杀）丢掉并截掉；整理到一半被打断（新 moov 已追加、旧 box 没改名）下次能识别并重来；已经是普通 MP4 的不动。任何异常都保留原文件（分段 MP4 本来也能播）。
  3. 控制条：停止后不再马上关掉，显示「正在保存…（百分比）」+ 底部进度条；GIF 显示「正在生成 GIF… N%」。好了变成绿色勾 +「已保存 · 大小」+ 视频时长，按钮换成「打开文件夹」「播放」「×」。中途出错保存了一部分时是橙色「已保存录到的部分」。20 秒不动自动收起（鼠标放上去不收）；开始新录制或截图时也收起。全屏录制隐藏了控制条的，保存时也显示出来。系统通知照常发。
  4. 启动 2.5 秒后扫录屏文件夹和备用文件夹里的 `*.mp4|webm|gif.part`：整理、改名、通知「上次的录屏没有正常结束，已恢复录到的部分」；0 字节的删掉；正在录的那个跳过。
- **测试**：`test/save_1_3_2.sh` 34 项（.part → .mp4、整理后没有 moof 且有时长、解码无错、控制条状态和按钮、自动收起、截图时收起、放弃不留文件、中途出错保存部分、GIF 进度、整理前后逐包 / 逐帧一致、重复整理、整理中断、截断文件、启动恢复、英文）。另外用 Benji 电脑上两段真实的 Windows 4K 录屏副本测过：整理前后 2915 / 5498 个音视频包完全一样，解码出来的每一帧一样。
